# cPanel Deployment Guide

This guide explains how to deploy your full-stack application (React Frontend + Node.js/Express Backend) to a shared hosting environment using cPanel.

Most modern cPanel hosting providers include a feature called **"Setup Node.js App"** (powered by Phusion Passenger). This allows you to host long-running backend processes natively on a paid domain.

## Prerequisites
- A cPanel account with the **Setup Node.js App** module enabled.
- SSH/Terminal access (optional, but highly recommended).
- A domain or subdomain configured in your cPanel.

---

## Step 1: Prepare Your App Locally

Before uploading, you must build the final production version of your application.
Because this app relies on client-side environment variables (like `VITE_SUPABASE_URL`), you must provide them *before* building.

1. Ensure your `.env` file contains your correct `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, and any database credentials (e.g. `MYSQL_HOST`, etc.).
2. Run the build command locally:
   ```bash
   npm run build
   ```
   *This compiles your frontend into static files and bundles your Node backend into a single `dist/server.cjs` file.*

3. **Package your files**: Create a ZIP archive containing **only** the following files and folders:
   - `dist/` (the entire folder generated by the build step)
   - `app.js` (the Passenger entry point)
   - `package.json`
   - `package-lock.json` (if available)
   - `.env` (contains your backend secrets like `GEMINI_API_KEY`, `MYSQL_PASSWORD`, etc.)

*(Note: Do **NOT** upload the `node_modules/` or `src/` folders. They are heavy and unnecessary for production).*

---

## Step 2: Upload to cPanel File Manager

1. Log into **cPanel**.
2. Open the **File Manager**.
3. Create a new folder for your app (e.g., `/home/username/myapp`). **Do not** put this directly in `public_html` for security reasons!
4. Upload your ZIP archive into the newly created `myapp` folder.
5. Extract the ZIP archive inside that folder.
6. Make sure the `.env` file is present (you may need to click "Settings" in File Manager and check "Show Hidden Files (dotfiles)" to see it).
7. Create an empty directory named `uploads` inside `myapp` if your app handles file uploads.

---

## Step 3: Setup Node.js App

1. Go back to your main cPanel dashboard.
2. Under the "Software" section, click **Setup Node.js App**.
3. Click **Create Application**.
4. Configure the following fields:
   - **Node.js version**: Choose the latest available (e.g., `20.x.x` or `22.x.x`).
   - **Application mode**: `Production` (Critical for the backend to serve the frontend files properly).
   - **Application root**: `myapp` (The folder you created in Step 2).
   - **Application URL**: Select your domain/subdomain from the dropdown.
   - **Application startup file**: `app.js`
5. Click **Create** or **Save**.

---

## Step 4: Install Dependencies

After creating the app, the Node.js setup page will show a section for "Dependencies".
1. Look for a button that says **Run NPM Install** and click it. 
   *(This reads your `package.json` and downloads only the required backend libraries directly onto the server).*
2. **Alternative (via Terminal)**: If the button fails or is missing, open the **Terminal** in cPanel, enter the virtual environment command shown at the top of the Node.js App page (e.g., `source /home/user/nodevenv/myapp/22/bin/activate`), and manually run:
   ```bash
   npm install --production
   ```

---

## Step 5: Start the Application

1. Go back to the **Setup Node.js App** page.
2. Click the **Restart** button for your application.
3. Visit your domain in the browser!

### Troubleshooting
- **503 Service Unavailable**: If you get this error, it means the backend crashed. Check the cPanel error logs (usually in the `stderr.log` file defined in the Node.js App settings, or in your main domain's Apache log) to see what went wrong. Ensure all required environment variables are in your `.env` file.
- **Port Errors**: The backend has been configured to dynamically accept the port assigned by cPanel (`process.env.PORT`). You do not need to manually change ports.
- **API 404 / Missing Frontend**: Make sure you set the Application Mode to **Production**. The server uses `process.env.NODE_ENV === 'production'` to know it should serve the compiled frontend from the `dist/` folder.
